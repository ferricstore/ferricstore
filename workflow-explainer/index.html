What is a Workflow?
Explained for Normal Humans.

Ever play a video game without save points and lose 3 hours of progress after dying on a boss? That is exactly what happens to software during crashes—until you give it durable workflows.

💡
The 10-Second Concept:

A Workflow is a multi-step recipe (1. Charge Card → 2. Reserve Stock → 3. Ship Package). FerricStore durably records explicit workflow state. After a worker crash, a replacement worker can reclaim the flow; fencing protects state writes, while external charges still need a stable idempotency key.

WHY WORKFLOWS MATTER

The Pain of Plain Code vs. The Peace of Mind

💀 The Nightmare (Without Workflows)

Volatile Memory & Blind Retries

When standard software crashes midway through a 5-step process, all progress in temporary RAM is erased. The server has amnesia.

  • 💸
    Double Billing: Customer is charged twice ($300 instead of $150) when the dumb retry script restarts from step 1.
  • 📦
    Ghost Inventory: Stock is deducted twice in the warehouse, causing phantom out-of-stock errors.
  • 🚨
    3:00 AM Engineer Pagers: Developers wake up to manually fix corrupt database rows and issue refunds.
  • 😡
    Angry Customers: Support inbox flooded with chargeback complaints and angry reviews.
🛡️ The Solution (With FerricStore)

Durable State & Guarded Effects

FerricStore commits explicit state transitions through the configured durable topology before moving forward.

  • ✓
    Explicit recovery: If the server dies, a replacement worker claims the committed state. Protect charges with a provider idempotency key.
  • ⚡
    Lease-based reclaim: A replacement worker can claim eligible state after lease expiry.
  • 😴
    Sleep Peacefully: Even if half your data center loses power, in-flight customer orders resume safely.
  • 😊
    Clear Recovery: Committed order progress remains inspectable, while provider idempotency keys protect payment and inventory calls.
COMMON QUESTIONS

Frequently Asked Questions

Why can’t I just use a regular SQL database like Postgres?
You can, but the application must implement and operate locking, lease renewal, fencing, recovery polling, and retry state machines. FerricStore provides these workflow primitives directly; transition latency still depends on deployment and durability settings.
What if a server hangs or pauses during garbage collection?
FerricStore uses fencing tokens. If a slow "zombie" server wakes up late and tries to write old data, FerricStore rejects its write immediately because a newer server has already taken ownership of the checkpoint.
Is this only for e-commerce?
Not at all! Durable workflows power AI Agent chains (planning → web search → summarizing), payment billing, KYC verification, data pipelines, background video rendering, and employee onboarding.

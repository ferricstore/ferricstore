Zombie Workers & Monotonic Fencing

When a worker freezes through lease expiry, a replacement can claim the flow with a newer fencing token. FerricStore rejects stale Flow mutations; external databases are protected only when the application also passes the token and the database enforces monotonic updates.

FerricStore Python SDK: Monotonic Fencing Tokens

# Pass the claim's fence into an external store that enforces it
from ferricstore import WorkflowClient, complete

client = WorkflowClient.from_url("ferric://127.0.0.1:6388")
flow = client.workflow(type="critical-database-sync", initial_state="sync")

@flow.state("sync")
def sync_inventory(job):
    # The DB update must compare/store this token transactionally.
    postgres.update_stock(
        job.payload["item_id"],
        job.payload["quantity"],
        fence=job.fencing_token,
    )
    return complete(result=b"synced")

flow.worker().run()

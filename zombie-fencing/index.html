🧟 WHEN AN OLD WORKER RETURNS

When an old worker comes back

A worker pauses. Another takes over with a newer owner number. When the old worker returns, FerricStore rejects its outdated write. External databases get the same protection only when the application passes the number and the database checks it.

🛡️ Safety boundary: FerricStore blocks an older owner number. Pass that number to an external store and have it reject older writes too.

Python SDK: pass the owner number to your database

# Pass the claim's owner number (fencing token) to an external store
from ferricstore import WorkflowClient, complete

client = WorkflowClient.from_url("ferric://127.0.0.1:6388")
flow = client.workflow(type="critical-database-sync", initial_state="sync")

@flow.state("sync")
def sync_inventory(job):
    # The DB update must compare/store this token transactionally.
    postgres.update_stock(
        job.payload["item_id"],
        job.payload["quantity"],
        fence=job.fencing_token,
    )
    return complete(result=b"synced")

flow.worker().run()

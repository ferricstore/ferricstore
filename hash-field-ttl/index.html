ADVANCED IN-MEMORY KV · SUB-KEY EXPIRY

Let parts of one record expire:
Use a field-level TTL for a login code or cart hold

A TTL (time to live) says when a value should expire. FerricStore supports native field-level TTLs on a compound hash with HEXPIRE / HPEXPIRE, so a login code or cart hold can expire while the rest of the same user record remains available.

1# FerricStore field-level expiry (HEXPIRE):
2# Store all user attributes in ONE compound hash:
3client.hset("user:42", {"name": "Alice", "role": "admin"})
4
5# Expire ONLY the transient 2FA code in 5 seconds:
6client.hset("user:42", "auth_2fa", "849201")
7client.hexpire("user:42", 5, fields=["auth_2fa"])
8
9# Expire cart item reservation in 10 seconds (parent key stays permanent):
10client.hset("user:42", "cart_hold", "sku_iphone16")
11client.hexpire("user:42", 10, fields=["cart_hold"])

⚖️ ARCHITECTURE COMPARISON

Two ways to expire a login code or cart hold

Compare separate keys with one compound hash whose selected fields have their own TTL.

CAPABILITY ❌ SEPARATE-KEY EXAMPLE ✓ WITH FERRICSTORE
Transient Attribute Storage Separate keys: The login code and cart hold live outside user:42:profile so each can expire on its own. One compound hash: All attributes live under user:42 with independent expiry timestamps.
Memory Overhead (1M Users) 3.2 GB in this model: 10,000,000 dict headers, robj structs, and jemalloc allocations. 320 MB in this model: 1,000,000 keys with compact internal field tables.
Atomic Updates Several keys: Updates to separate keys need coordination when they must change together. One record: Updates to fields in the same hash can use the single-shard path.
Code Simplicity The application manages several keys and their expiry commands. Native command: client.hexpire("user:42", 300, ["token"]).

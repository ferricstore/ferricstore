Do not read this as 104,696 three-step business processes. The fused benchmark records an already-known state chain in one durable command. No HTTP call, model inference, payment, or other application handler runs between its steps.

WHAT THE NUMBERS MEAN

Choose the execution model first

The useful question is not “which number is larger?” It is “does application code need to run between durable states?”

REAL APPLICATION WORK

54,060 worker-driven workflows/s

Workers claim a named state, run normal application code, and report a durable transition or completion. The measured Azure run used one tiny handler, so it measures orchestration capacity—not the speed of your business logic.

What does 54K mean?

One server started, coordinated, claimed, and durably completed roughly 54,000 one-state synthetic workflows each second while producers and workers ran together.

THROUGHPUT IS NOT LATENCY

What we actually know about response time

The worker run measured total time for one million workflows; the fused run measured end-to-end latency for its three-step batch command.

FERRICSTORE WORKER ≈18.5 s total time for 1,000,000 workflows

The Azure run completed one million live worker-driven workflows at 54,060 workflows/s across the create, claim, worker handler, and finish path.

FERRICSTORE FUSED 27 ms p99 for all 3 steps together · p50 18.1 ms
  1. 01

    Start Create the workflow and persist its first named state.

  2. 02

    Advance Persist the second named state in workflow history.

  3. 03

    Finish Persist the final named state and mark the workflow completed.

p50 equivalent18.1 ÷ 3 ≈ 6.0 ms/step
p99 equivalent27.0 ÷ 3 = 9.0 ms/step

Think of this as roughly 6–9 ms of total time per logical step. These are divided end-to-end totals, not separately measured step latencies; individual steps may take different amounts of time. No application code runs between them.

TEMPORAL CLOUD ≈850 ms documented three-Activity baseline

Temporal’s current performance guide gives an approximate three-Activity total latency of 850 ms with regular Activities, about 275 ms with Local Activities, and about 265 ms with Eager Start + Local Activities.

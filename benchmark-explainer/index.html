WHAT THE MATH MEANS

Three actions, not three database writes

FerricStore’s Python benchmark counts every claimed and applied workflow handler as one state action. With three states, the worker applies two transitions and one final completion.

Workflow creation is measured separately. Internally, each command can update state, indexes, history, leases, and storage records, so 216,240 commands/s must not be relabeled as database writes/s.

Measured vs. hypothetical

54,060 workflows/s × 3 = 162,180 state actions/s is correct arithmetic. The published run measured 54,060 workflows/s × 1 action, so a real three-step throughput run is still required.

THROUGHPUT IS NOT LATENCY

What we actually know about response time

A million workflows finishing quickly does not reveal how long an individual workflow waited.

FERRICSTORE Unknown p50 / p95 / p99 workflow latency

The Azure run reports throughput and aggregate elapsed time only. ≈18.5 seconds is the service time for all one million workflows—not 18.5 seconds per workflow and not 18.5 milliseconds.

DBOS ≈40 ms separate 2024 five-step average

DBOS published about 40 ms for a five-step transactional workflow averaged over 1,000 executions. That was a different experiment from the 43K workflows/s no-step throughput run.

TEMPORAL CLOUD ≈850 ms documented three-Activity baseline

Temporal’s current performance guide gives an approximate three-Activity total latency of 850 ms with regular Activities, about 275 ms with Local Activities, and about 265 ms with Eager Start + Local Activities.

TEMPORAL SERVICE LATENCY

API latency is not full workflow latency

Temporal separately publishes a 200 ms p99 per-region latency SLO. Its reference table shows p99 of 54 ms for Workflow Start, 40 ms for Signal, and 61 ms for Signal-With-Start. Those operations are only parts of a multi-step workflow.

Do not conclude “FerricStore is faster” from throughput alone.

FerricStore needs matched low-load and saturated three-step runs with end-to-end p50, p95, p99, and p99.9 before its latency can be compared with DBOS or Temporal.

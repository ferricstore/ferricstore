Keep progress.
Even after a crash.

FerricStore helps software keep track of tasks with several steps. It records progress so work can continue from a saved step after a crash, instead of starting the whole task again.

What is a workflow?

A workflow is a task broken into steps. To create a report, for example, you collect data, write a summary, then send it.

Your application does the work. FerricStore remembers which step it has reached and whether it should continue, try again later, or wait for someone’s approval.

    Your application asks FerricStore for work that is ready to start.

  2. 2

    Do the work

    The application carries out that step, such as writing the report’s summary.

  3. 3

    Save progress

    It tells FerricStore what is done and what should happen next.

What happens to unfinished work after a crash?

The part of your application doing the work has a time limit for holding it. If it stops and that time runs out, another can take over from the saved step. An unfinished step may run again, but the progress already saved stays recorded.

Some actions need extra care. If a step charges a card, for example, it should send the same payment reference when trying again. The payment provider must recognize that reference and prevent a second charge. Saving progress alone does not prevent duplicate payments.

Why not just use a queue?

A queue is a list of jobs waiting to be picked up. It works well when each job stands on its own.

But what if the hotel booking fails after the flight is booked? A workflow tracks the whole trip: what is done, what comes next, and what needs to be cancelled. You can still use queues to deliver the work.

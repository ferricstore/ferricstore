String Sets vs. Native Bloom Filters in Memory

Why modern high-traffic architectures use native probabilistic structures to protect databases.

CAPABILITY (10,000,000 ITEMS) ❌ RAW STRING SET (SADD) ✓ FERRICSTORE NATIVE BLOOM FILTER (BF.ADD)
RAM Footprint 950 MB - 1.8 GB: Stores full string payloads, dict entry pointers, and hash table metadata. ~11.98 MB bit array in this model: Based on 10M items and a 1% target false-positive rate; implementation overhead is additional.
Cache Penetration Attack Postgres Crash: If malicious bots query 50,000 bogus IDs, queries miss cache and hammer Postgres connection pools. Negative check: An unset required bit proves absence, so that request can skip SQL. Positive checks can include false positives.
Lookup Latency Hash-table path: Stores full keys and object metadata. Bitwise path: Compact membership test; measure latency on the target workload.
Built-in Structures Requires custom modules or external Redis Stack binaries. Native Engine Family: Bloom, Cuckoo, Count-Min Sketch (CMS), Top-K, and T-Digest out of the box.

## Design Specificity Verdict

**Mixed: authored content inside a template-driven visual system.** The scenarios, terminology, numbers, and failure arcs are unmistakably FerricStore. Benchmark Explainer, Split Lab, Travel Saga, and Zombie Fencing feel designed around their mechanisms. A larger group reuses nearly the same badge, oversized gradient headline, paragraph, Without/With capsule, current-view pill, four metrics, code, and simulation composition. Product specificity is high in the content but medium-low in composition and interaction design.

The deterministic scan found 65 signals across 21 HTML files: 55 style-pattern warnings and 10 quality warnings. The useful recurring signals were gradient headlines on all 21 surfaces, a heavily reused font treatment, and width transitions on progress elements. Several detector signals were contextual or false positives: the reported em-dash overuse came from Python divider comments; the side-tab rule caught 3px inset stripes; and flat hierarchy was under-read because the parser fell back to regex after optional HTML/CSS parser packages were unavailable.

No visual overlay was created. The live document exposed a read-only title property to the injection preflight, so mutation was rejected and no script was injected. Evidence instead came from fresh desktop/mobile browser tabs, viewport screenshots, geometry checks, interactions, console logs, and a complete route sweep.

## Overall Impression

This is a technically credible, unusually honest demo suite with excellent failure-and-recovery storytelling. The recurring emotional journey is catastrophe → technical warning → promised safety → delayed agency → recovery payoff. The recovery payoff is strong, but the experiments often arrive too late. On mobile, several routes require multiple screens of navigation, boundary notes, giant titles, prose, and comparisons before users can act. The ending is also weak: many demos trail into code, comparison, and reference material instead of closing with one learned outcome and a clear next experiment.

Cognitive load is high: 5 of 8 checklist criteria fail. Pages often combine persuasion, caveats, metrics, code, scenarios, playback, and simulation at once; control clusters commonly expose 7–9 choices. Grouping, visual hierarchy, and current-state visibility are strong, but progressive disclosure is limited.

## What’s Working

- Concrete systems storytelling: “last VIP seat,” “chunk #9,” “$50K approval,” “Day 21 recovery,” and “Generation 2” turn infrastructure behavior into visible consequences.
- Strong state choreography: active/pending/done states, current-run strips, replay/reset, and crash feedback make distributed behavior inspectable.
- Exceptional claim hygiene: the benchmark distinguishes measured from derived values, and boundary notes correctly qualify simulations and external effects.
- Technical reliability: the full desktop sweep found no load failures, console warnings/errors, duplicate IDs, missing image alt text, or page-level horizontal overflow. Mobile code overflow is generally contained inside scrollable code blocks.
- Real interaction feedback: catalog search showed a correct count and useful empty state; Split Lab enabled Crash only when appropriate and clearly explained the resulting failure and recovery actions.

## Priority Issues

### [P1] Core experiments arrive too late

On mobile, routes such as Beginner Queue, Cache Stampede, and Hot/Cold Storage reach roughly 8,000px, with the first meaningful control several screens down. The suite promises interactive demos but initially behaves like a marketing article.

Fix: compress navigation and the accuracy boundary into one disclosure row, constrain the title to roughly two lines, and place the primary scenario control and mechanism visualization within the first 700px. Start with one Run action, then reveal Metrics and Code. Suggested pass: `$impeccable layout`.

### [P1] Mobile navigation and workflow visuals clip

Architecture Comparison, Idempotency & Determinism, and Workflow Explainer truncate back links. Workflow Explainer hides the fifth station and delivery gate inside `overflow-x: hidden`, removing part of the causal story.

Fix: use a two-row header or compact icon-plus-label exit. Give stage tracks an explicit scroller with snap points, edge fade, and a position label, or stack them vertically. Enforce 44×44px targets for header links, filters, and source links. Suggested pass: `$impeccable adapt`.

### [P1] The shared marketing template erases each mechanism’s visual character

Cache stampedes, fencing tokens, fan-out barriers, field expiry, and cold-tier reads should not all begin with the same gradient headline and comparison capsule. Users remember the template more than the mechanism.

Fix: make the mechanism the hero—for example a caller swarm converging on one recompute, tokens racing through a monotonic gate, a 16-node fan-out with one retry, fields expiring inside a retained hash, or hot values falling into a cold tier. Suggested pass: `$impeccable shape`.

### [P2] Catalog and demo controls expose too many simultaneous choices

The catalog presents nine controls before 20 cards; several demos expose 7–9 actions at once. First-timers must decide how to operate a demo before understanding it.

Fix: reduce the root to four learning-oriented groups plus More. Within demos, sequence Scenario → Run → Inspect and place advanced jumps and code variants behind secondary disclosure. Suggested pass: `$impeccable distill`.

### [P2] Beginner and contextual help do not match the jargon burden

Beginner Queue leads with Celery, RabbitMQ, and Redis. Other routes introduce Raft, HLC IDs, fencing, durable closures, and at-least-once execution before establishing a plain-language model. “DIRECTION 11/15” exposes internal design taxonomy.

Fix: add a one-sentence “What you will see,” provide inline definitions, offer Concept / Run / Code layers, remove internal direction numbering, and rewrite Beginner Queue around enqueue → worker takes job → crash → lease expires → retry. Suggested pass: `$impeccable clarify`.

## Persona Red Flags

### Jordan — first-timer

- The recommended Workflow Explainer still introduces closures, fences, and idempotency before its “10-Second Concept.”
- Beginner Queue assumes knowledge of three competing systems in its headline.
- Eight catalog topics and 20 cards make the first choice harder than necessary.
- Most primary actions are not discoverable within five seconds on mobile.

### Sam — accessibility-dependent

- Positive foundation: native buttons, selected-state ARIA, polite live regions, visible focus styling, and reduced-motion handling appear across the suite.
- Several long app-style routes have an H1 but no H2 landmarks despite many visually distinct sections, making screen-reader navigation coarse.
- Workflow Explainer clips meaningful stage content at 390px.
- Root topic buttons are 38px high, Split Lab navigation links are about 32–38px, and benchmark source links are about 41px.
- Dense horizontally scrolling code at mobile zoom creates a difficult two-axis reading task.

### Casey — distracted mobile user

- Key actions often sit several screens below the top and outside the thumb zone.
- Back navigation clips on multiple routes.
- Refresh/reopen loses simulation progress.
- Mobile pages of roughly 7,000–10,000px make interruption recovery difficult without sticky progress or navigation.

## Minor Observations

- Add “Skip to simulation” links to long routes.
- Standardize “All Demos,” “Back to All Demos,” and “Back to Demo Gallery.”
- Replace “Current SDK pattern” with a meaningful version or date plus a one-line explanation.
- Root mobile hides GitHub without a compact overflow menu.
- Many H1s become 5–7 lines on mobile; a tighter title/subtitle hierarchy would preserve emphasis.
- Add a visible “scroll for more” affordance to horizontally scrollable code.
- The emoji-heavy accents add energy, but reliability pages would benefit from a calmer icon vocabulary.

## Questions to Consider

- If Beginner Queue had 30 seconds to teach one idea, should the first screen show competitor names—or a job being reclaimed after its lease expires?
- If every gradient headline and Without/With capsule disappeared, what visual mechanism would make Cache Stampede, Parallel Fan-out, and Zombie Fencing unmistakably different?
- Should the repeated catastrophe comparisons feel educationally neutral, or should the suite feel more like a calm, confident systems laboratory?
- Would every route teach faster if it opened directly in the experiment and revealed claim boundaries and code only after the first successful run?

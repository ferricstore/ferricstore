# Homepage introduction and UX review — 2026-09-12

Scope: the public homepage at index.html. Impeccable clarify guided the implementation; this is an implementation review, not a scored independent critique.

## Findings addressed

- The first view described the demo collection without defining FerricStore. It now names the product as an open-source workflow and queue server and explains why saved progress matters.
- Both primary choices previously sent visitors into demos before establishing a mental model. The primary action now leads to an on-page explanation; Demos remains a direct navigation link for returning visitors.
- The preview assumed knowledge of fencing tokens and named state. The replacement diagram distinguishes application execution from saved workflow state and uses one report example.
- Setup guidance was limited to general documentation links. The homepage now links directly to the getting-started guide, names the supported SDK languages, and states the current beta status.
- Technical boundaries crowded the route into the catalog. Crash behavior and simulation limitations now have separate native disclosures at the relevant points.
- Topic filters used tabs without associated tab panels. They now use a labelled button group with pressed-state semantics. The result count is announced, and empty results provide an accurately named reset action.
- Inherited dark-theme text had insufficient contrast on the light homepage. The homepage now explicitly uses the established ink, paper, and muted colors, including labels, placeholders, and empty states.

## Product evidence

FerricStore README and guides/getting-started.md at main commit 4f81e4fafc57538046970f16b26254cd6fc78c9b support product positioning, independent application handlers, lease-based ownership, saved state, SDK languages, local setup, and beta status. Existing documented at-least-once and external-effect boundaries remain explained. No benchmark values or individual demo behavior changed.

- Verified local assets, internal anchors, and all 20 demo route destinations exist. Both edited JavaScript files pass syntax validation and the diff passes whitespace checks.

- Impeccable detector returned no findings on index.html, but used its limited regex fallback because optional parser dependencies were unavailable. This does not certify full accessibility or computed contrast.

## Remaining scope

Individual demo interiors were not redesigned in this pass. Their detailed terminology and presentation still need to be considered separately from the new introductory homepage. Accessibility checks here are a targeted review, not a full assistive-technology audit.
